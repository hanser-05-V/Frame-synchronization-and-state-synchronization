# 002 — 预测与回滚机制详解

> 📊 **本篇配图：**
> - [006-联网预测回滚流程图.html](../charts-output/006-联网预测回滚流程图.html) — 与 001 共用，含回滚后重预测流程

## 一句话定位

预测与回滚是联网帧同步的**核心纠错机制**——预测让玩家获得即时反馈，回滚在服务器输入与本地预测不一致时自动修正。这个机制的设计目标是：**让玩家感觉不到网络延迟的存在**，同时保证所有客户端的最终状态一致。

---

## 设计意图

### 为什么不是"等到服务器确认再执行"？

```
同步等待模型（不用预测）：
  玩家按键 → 发服务器 → 等50-200ms → 收到帧 → 执行逻辑 → 动画
  ↑ 按键后过了200ms球员才开始动！完全不可玩！

预测模型：
  玩家按键 → 立即预测执行 → 动画先播（~0ms延迟）
  同时发服务器 → 服务器200ms后回帧 → 对比 → 99%情况一致
  ↑ 只有1%的情况不一致需要静默修正
```

---

## 设计逻辑（核心）

### 预测阶段：客户端大胆猜

```csharp
// EngineUpdate 中，如果没有新的服务器帧可消费：
// 将自己本地的输入当作下一帧数据，进行预测
if (_frameQueue == null || _frameQueue.Count == 0)
{
    // 取一个预测实体
    var matchEntity = _matchController.matchEntityPool.Get();

    // 拷贝确认态到预测态
    confirmedMatch.CopyTo(matchEntity);

    // 用本地输入驱动一帧
    matchEntity.frame += 1;
    _matchController.CopyInput(matchEntity, ref localInput);
    _matchController.UpdateGameState(matchEntity);

    // 存入预测队列
    _predictInputQueue.Enqueue(localInput);
    _predictMatchQueue.Enqueue(matchEntity);
}
```

### 回滚后重预测

回滚不只是重新算当前的帧——所有在 `_predictInputQueue` 中排队的后续预测帧都需要用新的网络输入**重新预测一遍**。因为其他玩家的操作变了，后面所有帧的状态都会变。

```
回滚前:
  确认帧100 → [预测帧101] → [预测帧102] → [预测帧103]
                  (这些预测帧用了错误的对手输入)

回滚后:
  确认帧100 → [用服务器帧101重算] → [预测帧102重新预测] → [预测帧103重新预测]
                  (正确)              (用修正后的输入)      (用修正后的输入)
```

---

## ⚠️ 实践注意

1. **回滚频次越高性能越差**——每次回滚都要重新跑历史帧的逻辑 + 重预测后续帧。`RollbackCount` 和 `RollbackCalcCount` 是性能关键指标。
2. **丢帧计数 = 预测失败的信号**——`LoseFrameCount` 增加意味着网络质量变差或对手行为不可预测（AI 行为不同于客户端预测）。
3. **单机模式不需要预测**——LocalBattleController 没有 `_predictInputQueue`，逻辑直接跑。
