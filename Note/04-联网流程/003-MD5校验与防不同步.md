# 003 — MD5 校验与防不同步

> 📊 **本篇配图：** 无独立配图，校验逻辑包含在 [006-联网预测回滚流程图.html](../charts-output/006-联网预测回滚流程图.html) 中

## 一句话定位

MD5 校验是帧同步的**安全网**——每 200 帧（约 6.6 秒）计算一次游戏状态的 MD5 哈希发给服务器比对，检测客户端是否出现了不同步。它不是核心同步机制（那是预测+回滚的工作），而是最后一道保险。

---

## 设计意图

帧同步理论上保证了确定性，但实践中仍然可能发生不同步：
- 内存越界修改了逻辑变量
- 未初始化的局部变量
- 多线程竞争导致数据错乱
- 不同版本的 System 代码混合

MD5 校验不是修不同步——而是**发现不同步**，然后可以触发断线/重连/上报。

---

## 设计逻辑

```csharp
// E:\帧同步\Script\...\RemoteBattleController.cs:326-341
private void ConfirmMatch(MatchEntity matchEntity)
{
    _matchController.ConfirmeMatchEntity(matchEntity);

    if (matchEntity.frame % BattleSetting.MD5CheckFrames == 0)  // 每200帧
    {
        // 发自己的 MD5
        RemoteBattleNetworkController.instance.SendCheckInfo(matchEntity, player);

        // 对战 AI 也发一份（独立进程可能有不同步）
        if (AIManager._pvpAgentAIID[player.ID] != 0)
        {
            RemoteBattleNetworkController.instance.SendCheckInfo(matchEntity, player);
        }
    }
}
```

### 校验什么？

`SendCheckInfo` 把整个 `MatchEntity` 序列化（所有玩家位置、球状态、比分...），计算 MD5 哈希，发给服务器。服务器比对所有客户端的 MD5 —— 大多数客户端一致 → 那个不一致的客户端不同步了。

---

## ⚠️ 实践注意

1. **MD5CheckFrames 可以配置**——`BattleSetting.MD5CheckFrames = 200`，频繁校验增加 CPU 负担但更快发现问题。
2. **AI 的 MD5 也发**——因为 AI 运行在独立的服务器进程，也可能跟客户端不一致（虽然理论上逻辑相同）。
