# 3–5 分钟演示脚本

## 00:00–00:30 项目问题与架构

“这是一个两客户端帧同步篮球 Demo。网络只转发每帧 8 字节输入，不转发 Transform；两个客户端独立运行相同的定点数模拟。真实远端输入迟到时，用完整世界快照回滚重演，并通过 WorldHash 验证收敛。”

画面展示 README 架构图和已启动的转发服务器。

## 00:30–01:20 双端启动和最小篮球闭环

先启动 Editor，再启动 Windows 客户端，展示服务器在两端到齐后共同放行。分别操作两名球员移动，用 `E` 抢自由球，按住并松开 `Space` 投篮。指出篮球状态从 `Free` 到 `Held`、`Airborne`，最终进入 `Scored` 或重新 `Free`。

## 01:20–02:20 100ms 延迟下预测、回滚和 WorldHash

展示本地球员即时表现和远端一帧缓冲。让一次远端实际输入与零输入预测不一致，指出纠错帧、恢复快照和重演日志；随后对比双方 Canonical Frame 的 WorldHash 已重新一致。强调视觉平滑属于表现层，不会反写确定性世界。

## 02:20–03:20 F9 共同结束与精彩回放

完成一次投篮后，在任一端按 `F9`。说明结束请求也是同步输入；记录器只消费已经纠正的稳定帧，并等候片段后摇。双方发布相同终局帧、恢复该帧世界、一起暂停，然后进入精彩回放。演示 `P`、`[`、`]` 和 `R`。

## 03:20–04:20 测试证据、模块取舍和明确边界

展示编译和测试摘要：确定性拾取、预测否决、不同预测持球者收敛、投篮纠正、稳定帧回放和终局恢复均有覆盖。说明服务器不是权威模拟，只负责配对、共同放行和输入转发。最后明确当前项目不做比分、AI、犯规、动态缓冲和录像持久化，因为本阶段目标是冻结一条清晰、可复现、可讲解的帧同步闭环。

## 结束语

“这个项目的重点不是篮球内容量，而是证明输入协议、确定性世界、预测回滚、表现纠正和赛后回放能在同一条双端链路上闭环，并留下可重复的验证证据。”
