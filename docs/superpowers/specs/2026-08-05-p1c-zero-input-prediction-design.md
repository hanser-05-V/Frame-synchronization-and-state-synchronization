# P1-C 零输入预测纠错设计

## 阶段目标

修复 `PredictionSystem.ResolveRemote` 把合法零输入预测永久排除在纠错之外的问题，同时保留原有冷启动保护。建立首份真实输入基线后，预测为静止、真实为投篮或移动时必须产生回滚错误帧。

本阶段不修改网络协议、远端帧映射、完整世界快照、回滚重演、Hash 或篮球模拟。

## 根因

当前条件以 `kv.Value.used._raw != 0` 区分可验证预测。零既可能表示“尚未收到任何真实输入时的冷启动默认值”，也可能表示“已经联网后的合法静止输入”。这两个语义被同一个数值判断合并，导致后者无法纠错。

## 采用方案

在 `PredictionSystem` 中增加明确的 `_hasActualBaseline` 状态，并在每条预测历史中记录 `canValidate`：

- `Init` 时 `_hasActualBaseline = false`。
- 尚未收到真实输入时产生的预测，`canValidate = false`。
- 收到首份真实输入后，后续预测无论 `_raw` 是否为零，`canValidate = true`。
- 查找错误预测时使用 `isPredicted && canValidate && used != actualRaw`。
- 第一份真实输入只建立基线，不会追溯误判此前的冷启动预测。

选择逐条保存资格，而不是查询时只看全局标记，是为了防止首份真实输入到达后把之前的冷启动预测追溯变成可验证状态。

## 数据流

```text
Init
→ 无真实数据：记录预测值 + 当时的 canValidate
→ 收到真实数据：只比较此前 canValidate=true 的预测
→ 找到最近错误预测：返回 errorFrame/correctRaw 并清理污染历史
→ 更新最近真实输入并建立真实基线
```

## 测试与验收

新增 `PredictionSystemResolveRemoteTests`，验证：

1. 冷启动零预测遇到首份非零真实输入时仍不触发回滚。
2. 首份真实零输入建立基线后，后续零预测遇到真实投篮时触发回滚。
3. 建立基线后的零预测遇到真实零输入时不触发回滚。
4. 建立基线后的非零预测遇到不同真实输入时继续触发回滚。
5. 多个错误预测仍选择最新帧，并只清理该帧及后续历史。
6. 全部 EditMode 测试通过，编译错误为零。

## 风险边界

`ResolveRemote` 仍沿用“用当前到达的真实值近似校验此前预测”的既有算法。本阶段只修复预测资格的语义混淆，不把它扩展为逐远端帧真值对照。
