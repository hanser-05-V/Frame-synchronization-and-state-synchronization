## 目标

在不改变确定性逻辑、输入预测、回滚重演、网络协议或 WorldHash 的前提下，把远端表现时间线固定后移一个逻辑帧，降低固定 100ms 延迟下远端停止和变向纠正的可见回抽。

本阶段采用自动轨迹断言与双端人工观察共同验收。0ms 模式负责确认现有玩法和本地响应没有退化；固定 100ms 模式覆盖远端启动、停止、同向续行、快速变向和远端持球移动。

## 已确认事实

- 逻辑帧率约为 30FPS，单帧间隔为 33ms。
- 移动速度为每秒 5 个世界单位，单个逻辑步长约为 `5 × 0.033 = 0.165`。
- 当前表现插值器保存 `N-2/N-1/N` 三个完整端点。
- 当前本地玩家使用 `N-1 → N`，远端玩家使用 `N-2 → N-1`。
- 当前远端总表现延迟约为两个逻辑帧，即约 66ms。
- 当前回滚表现纠正器会保存回滚前显示位置，限制纠正速度，在最长 0.2 秒内衰减误差，并在完成时精确到达最新目标。
- 当前篮球表现端点同时保存坐标、状态、持球者和 Held 挂点偏移。

## 术语边界

- **缓冲容量**：能够保存多少历史端点。
- **目标水位或播放延迟**：渲染读取位置相对最新逻辑端点落后多少帧。
- 只扩大容量而不后移读取位置，不会增加抗抖动能力，也不会改变当前画面。
- 本阶段同时增加一个端点并把远端读取区间后移一帧，因此远端表现延迟增加约 33ms。
- 输入缓冲、快照历史容量和表现端点缓冲是不同数据结构，本阶段只修改表现端点缓冲。

## 范围

### 纳入范围

1. 将表现端点从三个扩展为四个：`N-3/N-2/N-1/N`。
2. 本地玩家继续使用 `N-1 → N`。
3. 远端玩家改用 `N-3 → N-2`，总表现延迟约为 99ms。
4. 本地 Held 篮球保持本地低延迟时间线。
5. 远端 Held、Free、Airborne 和 Scored 篮球使用 `N-3 → N-2` 深时间线。
6. 回滚后一次性用纠正后的 `N/N-1/N-2/N-3` 替换全部表现历史。
7. 增加四端点、球权切换、回滚历史和固定 100ms 轨迹测试。

## 方案选择

采用“深化现有插值器为四端点固定缓冲”。不在现有插值器旁增加第二套远端缓冲，避免 Reset、正常推帧、回滚替换和球权切换维护两份历史。

不采用远端只显示确认世界。该方案更能避免展示预测错误，但远端延迟会随确认进度变化，可能超过本阶段批准的额外一帧上限。

不采用动态水位。动态水位还需要延迟和抖动估计、缓冲升降策略、时间伸缩及欠载处理，超过首轮范围。

## 四端点时间模型

插值器固定保存四个严格递增的完整表现端点：

```text
最深端点       最旧端点       前一端点       当前端点
   N-3  ─────────  N-2  ─────────  N-1  ─────────  N
        远端深时间线                    本地时间线
```

同一个渲染 `alpha` 驱动两条时间线：

```text
本地玩家 = Lerp(N-1.player, N.player, alpha)
远端玩家 = Lerp(N-3.player, N-2.player, alpha)
```

本地时间线不变；远端相对当前实现再落后一帧。`alpha` 仍只服务表现层，不进入实体、输入、快照、重演或 Hash。

## 篮球与球权时间线

每个端点必须从同一逻辑快照复制以下篮球数据：

- 绝对坐标；
- `BallEntity.EState`；
- `holderPlayerIndex`；
- Held 状态下相对持球人表现基准的挂点偏移。

禁止用最新帧球权解释历史帧坐标。

### 本地 Held

当最新端点 `N` 表示篮球由本地玩家持有时：

- 篮球使用 `N-1 → N`；
- 篮球附着到本地玩家的最终显示位置；
- Held 挂点偏移在两端都由同一本地玩家持有时插值，否则使用新端点偏移；
- 本地持球移动不增加额外表现延迟。

### 远端 Held

只有深时间线的新端点 `N-2` 已表示篮球由远端玩家持有时，篮球才表现为远端附着：

- 篮球和远端持有者共同使用 `N-3 → N-2`；
- Held 挂点偏移来自同一对深时间线端点；
- 远端逻辑头 `N` 的新球权不能提前解释 `N-3 → N-2` 的历史坐标。

### Free、Airborne 和 Scored

三种非附着状态统一使用篮球绝对坐标 `N-3 → N-2`。这样远端出手、落地和得分不会比远端球员时间线提前一帧。

### 本地球权离开

当最新端点 `N` 不再是本地 Held 时，篮球立即退出本地附着并转入深时间线。深时间线端点仍可能处于历史本地 Held 状态，但此时按未附着绝对坐标播放，不继续绑定当前本地玩家。

该切换可能让本地出手后的空中轨迹比本地 Held 阶段多约一帧表现延迟。这是保持非附着篮球与远端世界时间一致的已批准取舍。附着键从本地玩家变为 `-1` 时，沿用现有篮球表现纠正，从切换前显示位置连续接入深时间线目标。

### 远端球权进入和离开

- 远端获得球权在 `N-2` 到达深时间线后才附着。
- 远端失去球权在 `N-2` 已表示非 Held 后才退出附着。
- 附着和解绑都以深时间线端点为准，不读取逻辑头 `N` 提前切换。
- Held 篮球继承持有者的显示纠正；未附着篮球使用独立纠正器。

## 正常推帧、初始化和追帧

- Reset 后四个端点全部复制同一个有效世界，任意 `alpha` 返回同一结果。
- 正常逻辑帧必须严格递增。
- 每次推帧按 `deepest ← oldest ← previous ← current ← new` 轮转。
- 一次 Unity Update 追赶多个逻辑帧时，每个完整逻辑帧依次推入；最终只保留最后四个连续端点。
- 一个 Unity 渲染帧仍只求值一次并写一次 Transform。

## 回滚历史替换

设回滚重演后的最新执行帧为 `N`：

1. `GameController` 从 `PredictionSystem` 读取纠正后的 `N`。
2. 若存在，继续读取连续的 `N-1/N-2/N-3`。
3. `PresentationFrameInterpolator` 在一次调用中替换四个端点。
4. 替换完成后重新计算本地、远端和篮球表现样本。
5. 回滚前 Transform 只作为表现纠正起点，不作为球权或逻辑状态来源。

历史不足时使用以下确定规则：

- 缺少 `N-1`：前一、最旧和最深端点全部复制 `N`。
- 有 `N-1`、缺少 `N-2`：最旧和最深端点复制 `N-1`。
- 有 `N-2`、缺少 `N-3`：最深端点复制 `N-2`。
- 任一可选快照若存在但帧号不连续或内容无效，明确拒绝调用，不拼接不连续历史。
- 最新快照 `N` 缺失时，沿用当前降级路径，把全部表现端点压缩到纠正后的实时世界并记录错误。

任何降级都禁止保留回滚前的旧预测端点。

## 残余表现纠正

固定增加一帧的首要作用是让更多预测错误在进入显示区间之前被纠正。它不能对超过缓冲窗口的延迟或抖动提供数学上的绝对保证。

首轮保留当前 `PresentationCorrectionSmoother`：

- 回滚首段保持显示速度连续；
- 背离纠正目标时先减速，再进行必要的有限反向；
- 纠正速度受上限约束；
- 纠正最长不超过 0.2 秒；
- 完成时精确到达最新表现目标；
- 超过跳转距离时沿用现有直接跳转策略。

“禁止反向纠正”不是运行时绝对不变量。若正确目标停在显示位置后方，永久禁止反向会导致永不收敛。本阶段真正的验收目标是：在批准的固定 100ms 场景中，新增缓冲把纠正反向位移压到不可见阈值以内，同时仍保证限时精确收敛。

如果新增轨迹测试证明当前纠正器超过阈值，停止实现并向帅老大汇报；另行设计远端专用纠正策略，不直接修改公共纠正器。

## 自动测试

### 四端点与玩家时间线

- Reset 后四槽一致。
- 连续推入四帧后，本地严格使用 `N-1 → N`。
- 远端严格使用 `N-3 → N-2`。
- 本地玩家索引为 0 或 1 时结果对称。
- `alpha=0/0.5/1` 返回精确端点和中点。
- 多帧追赶后只保留最后四个连续端点。
- 重复、倒退帧和非法参数明确失败。

### 篮球时间线

- 本地 Held 使用本地时间线和本地挂点。
- 远端 Held 使用深时间线、远端持有者和同帧挂点。
- 远端逻辑头刚获得球权时不得提前附着。
- 远端 Held → Airborne 在深时间线到达释放帧时解绑。
- Free、Airborne 和 Scored 使用深时间线绝对坐标。
- 本地 Held → Airborne 立即退出当前本地附着，并连续接入深时间线。
- 球权切换后不继续挂在旧持有者，也不提前挂到新持有者。
- Held 篮球最终位置等于持有者最终显示位置加同时间线挂点偏移。

### 回滚替换

- 纠正后的 `N/N-1/N-2/N-3` 一次性替换全部预测端点。
- 球权、持有者、位置和挂点全部来自纠正后快照。
- 缺少历史时按最近可用纠正端点逐级复制。
- 无效或不连续的可选快照被拒绝且不部分修改现有缓冲。
- 替换和求值不修改逻辑实体、快照或 WorldHash。

### 固定 100ms 轨迹

新增纯表现轨迹回归，至少覆盖远端启动、停止、同向续行、快速反向和远端 Held 移动。

量化标准：

- 一个逻辑步长为 0.165 世界单位。
- 停止和同向续行场景中，沿纠正前运动轴累计的非预期反向位移不得超过一个逻辑步长的 10%，即 `0.0165`。
- 快速反向场景允许权威输入导致的一次真实转向，但不得出现二次回抽；显示路径相对纠正后深时间线的额外反向偏差不得超过 `0.0165`。
- 单次表现纠正不得超过 0.2 秒。
- 纠正完成后与最新表现目标的误差不得超过 `0.0001`。
- 远端 Held 篮球与持有者的挂点误差不得超过 `0.0001`。
- 本地玩家的时间线输出必须与修改前相同。

自动轨迹通过不替代人工观感验收。

## 人工验收

### 0ms

1. 两端分别操作本地玩家，确认本地启动、停止和变向没有新增一帧延迟。
2. 完成移动、拾取、投篮、得分或落地回 Free。
3. 本地 Held 篮球稳定跟手；投篮后无持续人球分离。
4. 回滚、终局帧和精彩回放既有能力无退化。

### 固定 100ms

1. 远端持续直线移动后停止，不能观察到明显向后回抽。
2. 远端同向续行不能出现短暂反向。
3. 远端快速变向只出现一次符合输入语义的转向，不出现二次回抽。
4. 远端持球移动时人球保持同一时间线，无提前附着或提前离手。
5. 远端投篮、落地和重新拾取时球权与位置切换连续。
6. 本地角色不因远端缓冲增加操作延迟。
7. 最终双方逻辑世界和同一 canonical frame 的 WorldHash 收敛。

## 失败处理

- 四端点帧号不连续时拒绝替换，不静默接受错误时间线。
- 最新纠正快照缺失时记录明确错误并压缩到纠正后的实时世界。
- 历史不足只复制纠正后端点，不恢复旧预测历史。
- 自动轨迹超过批准阈值时，不放宽断言，不直接改公共纠正器；停止并重新设计。
- 0ms 本地响应退化、远端人球分离或 Hash 不收敛都属于阻塞失败。
- Unity 已运行时不并行启动第二个无界面实例。
