# 赛后精彩片段回放与屏幕操作说明设计

日期：2026-08-10

## 目标

将现有的 R/P 本机录制回放替换为赛后精彩片段回放：正常比赛期间自动识别成功投篮，保存纠正后的短片；玩家按 F9 请求结束比赛后，进入独立回放阶段。回放不得重置联网帧号、不得继续修改正式比赛世界，也不得重新引发预测或回滚。

同时在 Game View 左上角常驻显示当前阶段真正可用的按键，避免继续暴露联网模式下不安全或尚未实现的操作。

本设计参考只读《街篮2》生产源码中的 `SnapshotSystem`、`SnapshotReplayFrameBuffer` 和 `SnapshotReplayBattleController`：正式比赛维护滚动历史，由事件选取精彩片段，赛后交给独立控制器播放。本 Demo 保留该分层，但采用更适合小世界状态的逐帧 `FrameSnapshot`。

## 非目标

- 不实现整场录像文件、录像分享或跨进程持久化。
- 不实现慢动作、专用回放摄像机或镜头评分。
- 不恢复旧式 R 开始录制、P 从当前世界倒回模拟的行为。
- 不新增比分、比赛倒计时或服务器控制消息。
- 不改变现有 8 字节网络输入包结构。

## 方案选择

采用“纠正后的逐帧世界快照”。每个片段保存完整 `FrameSnapshot` 序列，回放时只读取序列并更新表现对象。

与“起始快照 + 输入重演”相比，该方案不会把预测输入重新带入赛后回放，也不依赖已经清理的远端输入字典。当前世界仅有两名球员和一个篮球，单帧快照很小；最多三个约 3.5 秒的片段，内存成本可控。

## 运行阶段

新增两个显式阶段：

1. `Playing`：帧同步、预测、回滚和精彩事件扫描正常运行。
2. `PostGameReplay`：正式帧引擎停止，不再发送本地操作、不再处理回滚；独立回放控制器只驱动表现对象。

阶段切换只能由已经稳定的 F9 输入触发，不能由预测输入触发。

## F9 结束比赛的同步规则

使用 `FrameInput.buttons` 的 bit 6 表示 `endMatchPressed`，仍包含在原有 4 字节 raw input 中，因此网络包继续保持 8 字节。该按键属于一次性动作，必须加入预测清除掩码；远端未收到真值时绝不预测结束比赛。

两端分别扫描已经稳定的输入帧：本地输入来自 `FrameBuffer`，远端输入来自按帧保存的实际网络输入。TCP 保序，因此 `latestRemoteFrameID` 之前的远端帧可视为连续稳定区间。任意一名玩家在稳定帧按下 F9，两端都会得到同一个结束请求帧。

如果最后一个成功投篮片段尚缺少进球后的尾帧，比赛继续运行到该片段收尾完成，再进入 `PostGameReplay`；屏幕显示“比赛结束请求已确认，正在收尾精彩片段”。没有待收尾片段时立即进入赛后阶段。

## 精彩片段捕获

### 稳定帧扫描

精彩事件不直接相信正常预测帧产生的临时状态。每次完成本帧可能的回滚后，扫描新增长的稳定快照区间：

- `Held -> Airborne`：记录本次投篮的 `shotFrame`。
- `Airborne -> Scored`：确认成功投篮，创建待完成片段。
- `Airborne -> Free`：确认投失，清除本次投篮锚点，不生成片段。

稳定扫描发生在回滚处理之后，因此读取的是 `PredictionSystem` 已经覆盖纠正过的世界快照。

远端接收线程的“最新到达帧”不能直接作为稳定上界。远端输入只有在
`ResolveRemote` 完成真值校验，且本次预测错误所需的回滚成功结束后，才由
`StableRemoteFrameGate` 发布给精彩片段扫描；刚进入接收字典但尚未校验的帧
继续保持不可见。

若确认延迟超过环形缓存容量，最早的输入或快照可能已经不可恢复。此时扫描器
明确放弃跨越缺口的未完成片段，并从当前仍保留的第一帧重新建立连续序列，
同时输出一次错误；不得永久停在已覆盖的帧号上。

### 默认窗口

- 起点：`shotFrame - 60`，即投篮前约 2 秒；小于 0 时截断为 0。
- 终点：`scoreFrame + 45`，即进球后约 1.5 秒。
- 最大数量：本场最近 3 个成功投篮片段，超出后移除最早片段。

当稳定帧已经覆盖片段终点时，从 `PredictionSystem` 复制 `[startFrame, endFrame]` 的完整快照。任何一帧缺失时放弃该片段并输出一次明确错误，不生成残缺回放。

片段元数据包含：起止帧、投篮帧、进球帧、投篮球员索引以及快照数组。

## 赛后回放控制器

独立 `PostGameHighlightReplayController` 持有只读片段列表，不持有网络和预测系统引用。

- 进入赛后阶段时自动播放第一段。
- 使用未缩放时间按 33ms/帧推进，并在相邻快照间插值表现位置。
- 当前片段结束后自动播放下一段；最后一段结束后停在末帧。
- `P`：播放/暂停。
- `[`：上一段并从头播放。
- `]`：下一段并从头播放。
- `R`：当前片段从头播放。
- 没有成功投篮片段时保持正式世界最后画面，并显示“本场暂无精彩片段”。

回放只写入球员和篮球 GameObject 的表现坐标，不写入 `PlayerEntity`、`BallEntity`、`PredictionSystem` 或 `FrameBuffer`。因此退出或重复播放不会改变正式比赛结果。

## 屏幕操作说明

新增独立 `RuntimeControlOverlay`，运行时由 `GameController` 创建，不依赖被忽略的 Scene 资源，也不依赖现有调试 Canvas 层级。使用轻量 `OnGUI` 在左上角绘制半透明面板。

`Playing` 阶段显示：

- `WASD`：移动本机球员
- `E`：靠近自由球时拾取
- `Space（松开）`：持球时投篮
- `F9`：结束比赛并进入精彩回放
- `Esc`：退出

`PostGameReplay` 阶段显示：

- `P`：播放/暂停
- `[` / `]`：上一段/下一段
- `R`：重播当前片段
- `Esc`：退出
- 当前片段序号、原始帧范围及播放状态

旧的 `R/P/C` 本机录放与重置入口不再响应；联网模式下不显示 F10，因为它已被明确禁止。尚未接入玩法逻辑的传球、抢断、盖帽和冲刺也不显示。

## 组件边界

- `StableFrameCursor`：计算并单调推进可扫描的稳定帧上界。
- `HighlightReplayRecorder`：从稳定快照和稳定输入识别投篮、得分与 F9，生成最多三个片段。
- `HighlightClip`：不可变片段数据和元数据。
- `PostGameHighlightReplayController`：只读片段播放游标、切换和插值。
- `RuntimeControlOverlay`：根据阶段和回放状态生成屏幕文案。
- `GameController`：只负责连接这些模块和执行阶段切换，不承载片段筛选算法。

## 失败处理

- 快照范围不完整：跳过该片段并记录起止帧及首个缺失帧。
- F9 到来但片段仍在收尾：继续正式模拟，并在 UI 显示等待状态。
- 本场没有成功片段：允许进入赛后阶段，显示空状态，不抛异常。
- 回放索引越界：控制器进行边界夹取；只有一个片段时上一段和下一段均保持当前片段。
- 重复 F9：第一次稳定请求生效，后续请求忽略。

## 测试策略

EditMode 回归测试至少覆盖：

1. `endMatchPressed` raw 位域与预测清除。
2. 稳定游标不越过最新远端实际帧且只单调前进。
3. 成功投篮生成 `[shot-60, score+45]` 片段。
4. 开局附近投篮将起点夹到 0。
5. 投失不生成片段。
6. 预测产生但纠正后消失的得分不生成片段。
7. 第四个片段加入后移除最早片段。
8. 缺失快照时整段拒绝保存。
9. F9 等待尾帧完成后才切换阶段。
10. 回放播放、暂停、重播、上一段和下一段的边界行为。
11. 回放采样不会修改传入的正式逻辑实体。
12. 两个阶段的屏幕操作文案只包含真正可用按键。

人工双端验证：

- 双端世界 Hash 在比赛阶段保持一致。
- 任一端按 F9 后，两端识别相同结束请求帧并进入赛后阶段。
- 每个片段显示的起止帧一致，球员和篮球没有起播位置偏移。
- 重播或切换片段不会出现回滚日志、网络发送或正式世界状态变化。

## 完成标准

- R/P 不再重置 `FrameEngine._currentFrame`。
- 成功投篮自动生成最多三个可播放片段。
- F9 能结束当前测试比赛并进入独立赛后回放。
- 回放位置来自纠正后的快照，起播无位置偏移。
- 屏幕始终显示当前阶段的真实可用操作。
- 现有帧同步、篮球、预测、回滚和服务端协议测试继续通过。
