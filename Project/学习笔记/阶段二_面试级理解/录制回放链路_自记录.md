## 我的理解（原始记录）

录制流程

FramController 初始化 Init() 
{
    FramDebugger字段信息
    初始化
    向 FramEnigine 添加事件注册 —> FramEnigine update(检测帧，录入输入，逻辑帧执行，追帧触发)
}

update()
{
    检测输入 按下R（先记录当前位置，调用 FramDebbger 开始录制信息）
    按下 P回放键（先暂停录制，重置位置，调用 FramDebbugger 回放）
}

FramDebuuger: 包含当前记录帧和玩家回放帧，记录帧在开启记录时候开启递增，
回放时候玩家回放帧增加，当超过记录帧就回放结束

## 🦉 架构导师审查

### 逐段评分

**段落 1：Init() — ⚠️ 部分对**

| ✅ 对的 | ❌ 缺的 |
|--------|--------|
| "向 FrameEngine 添加事件注册" 方向正确 | 没说注册了几个回调、每个回调干什么 |
| | 没说 FrameDebugger 和 GameController 的关联（`FrameDebugger.Instance` 单例） |

**段落 2：Update() — ⚠️ 关键错误**

| ✅ 对的 | ❌ 错的/缺的 |
|--------|------------|
| R 触发录制、P 触发回放——方向对 | "R键先记录当前位置"——源码中 R 键不记录位置！**P 键才记录位置**（用于回放后复原） |
| | 缺了 C 清空录制、Space 暂停/恢复 |
| | 缺了 ReadInputs() 的三种模式——这是链路核心 |

**段落 3：FrameDebugger — ✅ 基本对**

| ✅ 对的 | ❌ 缺的 |
|--------|--------|
| recordedFrameCount 递增、playbackFrame 递增、超限结束 | 录制每帧存的到底是什么——`inputs[i]._raw`（4字节uint） |
| | 回放时 Input 怎么替换键盘输入——`ReadInputs()` 里的 `if(isPlayingBack)` 分支 |

### 总评

对「**什么时候触发**」理解是对的（R→录制、P→回放、计数器递增），但漏了「**数据怎么流动**」——这才是核心。

## ✍️ 架构导师修正版

### 正确链路

```
按下 R:
  GameController.Update() 检测到 R 键
    → FrameDebugger.Instance.StartRecording()
        → recordedInputs.Clear()
        → recordedFrameCount = 0
        → 重置 FrameEngine._currentFrame = 0（反射）

每帧（录制中）:
  FrameEngine.ExecuteOneFrame()
    → FrameDebugger.UpdateFrame(frameID, inputs, ...)
        → recordedFrameCount++
        → recordedInputs.Add(inputs[i]._raw)   ← 每帧每玩家存一个 4 字节 uint

按下 R 第二次:
  GameController.Update() 检测到 R 键
    → FrameDebugger.Instance.StopRecording()

按下 P:
  GameController.Update() 检测到 P 键
    → 保存方块当前位置（recordStartPositions）
    → 方块回到录制起点
    → FrameDebugger.Instance.StartPlayback()
        → playbackFrame = 0
        → 重置 FrameEngine._currentFrame = 0

每帧（回放中）:
  FrameEngine 回调 OnRequestInput
    → GameController.ReadInputs()
        → if (isPlayingBack):
              recordedInputs[playbackFrame * playerCount + playerIndex]  ← 不读键盘！
    → 相同 Input → 相同 FixedInt 计算 → 相同轨迹 ✨
```

### 伪代码

```csharp
// ===== 录制回放 完整伪代码 =====

List<uint> recordedInputs;    // 录制存储（每个 uint 是一个玩家的 4 字节 Input）
bool isRecording, isPlaying;
int recordedFrames, playbackFrame;
Vector3[] savedPositions;     // 回放前保存的位置（用于复原）

// ── 按 R：开始录制 ──
void StartRecord()
{
    isRecording = true;
    recordedInputs.Clear();
    recordedFrames = 0;
    ResetEngineFrameToZero();
}

// ── 每帧：录制存 Input ──
void OnFrame(int frameID, FrameInput[] inputs)
{
    if (isRecording && !isPlaying)
    {
        recordedFrames++;
        for (int i = 0; i < inputs.Length; i++)
            recordedInputs.Add(inputs[i]._raw);   // ← 录制的本质：每帧存 4 字节
    }
}

// ── 按 R 第二次：停止录制 ──
void StopRecord() { isRecording = false; }

// ── 按 P：开始回放 ──
void StartPlayback()
{
    savedPositions = GetCurrentBlockPositions();  // 保存位置（回放结束复原）
    ResetBlocksToRecordStart();                   // 回到录制起点
    isPlaying = true;
    playbackFrame = 0;
    ResetEngineFrameToZero();
}

// ── 每帧：回放读 Input（不读键盘！） ──
FrameInput ReadInput(int playerIndex)
{
    if (isPlaying)
    {
        int idx = playbackFrame * playerCount + playerIndex;
        if (idx >= recordedInputs.Count) return FrameInput.Zero;
        return FrameInput.FromRaw(recordedInputs[idx]);  // ← 回放的本质：从列表读
    }
    return ReadKeyboard(playerIndex);                    // 正常：从键盘读
}

// ── 回放结束 ──
void OnFrameEnd()
{
    if (isPlaying)
    {
        playbackFrame++;
        if (playbackFrame >= recordedFrames)
        {
            isPlaying = false;
            RestorePositions(savedPositions);  // 复原位置
        }
    }
}
```

## 📋 我的 4 个坑（纠正记录）

| # | 我之前写的 | 问题 | 正确 |
|---|-----------|------|------|
| 1 | "按R：先记录当前位置" | R 键不记录位置 | **P 键**才保存位置（回放结束复原用） |
| 2 | 没说 ReadInputs 的三种模式 | 这是链路核心 | 正常(读键盘) / 回放(读列表) / 暂停(返空) |
| 3 | 没说录制每帧存的是什么 | 这是录制的本质 | `inputs[i]._raw`（4 字节 uint） |
| 4 | 没说回放 Input 怎么替换键盘 | 这是回放的本质 | `ReadInputs()` 里 `if(isPlayingBack)` 分支替换输入源 |
