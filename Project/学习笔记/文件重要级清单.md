## 📝 阅读记录

### L2-3 FrameBuffer.cs — 2026-07-03

**核心理解：**
- 帧数据仓库，容量 256 帧（环形数组，`frameID % 256` 定位）
- 内部 Frame struct：帧号 + 玩家数 + Input 数组
- 两个指针：`_maxWrittenFrame`（写到哪）、`_lastReadFrame`（消费到哪）
- 对外方法：AddFrame（写入+连续检测）、GetFrame（消费）、PeekFrame（只读不消费）、HasFrame、MarkRead
- BufferSnapshot 独立 struct，只为可视化拍快照

**补充纠正：**
- PeekFrame ≠ GetFrame：Peek 不更新读指针，用于回放对比时偷看
- MarkRead 被 FrameEngine 以 `frameID - 4` 延迟调用，制造"待消费"黄色格子的视觉效果
- AddFrame 的连续帧检测：`frameID != _maxWrittenFrame + 1` → 拒绝写入

### L2-4 FrameEngine.cs — 2026-07-03

**核心理解：**
- 启动记录绝对时间戳 (`_startMs`)，Update 里检测 `总耗时 - 上一次逻辑帧 ≥ 33ms` 才执行
- while 循环追帧：间隔超过 33ms 就多跑一帧，一轮 Update 可能跑多帧
- ExecuteOneFrame 6 步：① 拉取输入 → ② 写入缓冲 → ③ 更新时间 → ④ 通知逻辑层 → ⑤ 延迟 MarkRead → ⑥ 同步 Debugger
- `MarkRead(frameID - 4)`：回拉 4 帧标记消费，模拟联网时的缓冲待消费效果

**纠正：**
- `MarkRead(frameID - 4)` **不是模拟回滚**，而是**模拟网络缓冲延迟**。联网时帧数据从服务器过来有延迟，缓冲区里自然有"已写但未确认"的帧（黄色格子）。单机下没有这个延迟，所以手动滞后 4 帧——纯粹视觉效果
- 回滚（Rollback）是另一个概念——回滚在 `FrameEngine` 里不存在，要到联网阶段的 `RemoteBattleController.ReCalculate()` 才有
