## 第一次考核 — 单机帧同步基础

> 时间：2026-07-01
> 背景：完成单机帧同步 Demo（FixedInt + FrameBuffer + FrameEngine + 录制回放 + 双视图）

### Q1：单机项目不联网，为什么不直接用 float？

**帅老大回答：**
float 会有精度问题，根据不同设备的性能会有差异，这样就不能保证用户输入的准确性，得到的结果会有偏差。

**评价：** ✅ 通过

**纠正补充：**
同一个 CPU、同一个 exe、同一次运行中，float 运算其实是确定的。帧同步用定点数的真正原因是**跨场景**的不确定性——IL2CPP vs Mono、x86 vs ARM、Debug vs Release——这些会导致 float 结果不同。定点数解决的是"录制的回放在任何机器上都能源代码复现"。

---

### Q2：录制了 100 帧 Input，回放时只喂 Input 不记录碰撞。方块在第 50 帧撞墙怎么办？

**帅老大回答：**
因为记录了录制时候的开始帧位置，以及这段时间的输入，他必定是以同样的状态发生碰撞，所以也不需要记录碰撞。

**评价：** ✅ 满分

**要点：**
只存"因"（Input + 起点），不存"果"（碰撞 / 轨迹）。"果"由"因"通过确定性逻辑自然计算出来。只要逻辑代码是确定性的（同一个 FixedInt、同一个 System 执行顺序），给定相同的 Input + 起点，碰撞时机、位置、结果必然完全一致。

---

### Q3：Demo 里 FrameBuffer 每写一帧立刻 MarkRead。主程说"这跟直接调 Update 没区别"——说得对不对？

**帅老大回答：**
目前单机测试下缓冲区确实几乎没有延迟就下发命令了。但是后续接入网络后便会体现出作用——客户端发送输入指令进入待缓冲区，服务器接受下发命令到缓冲区，最后客户端按照一定步长来进行处理。目前运动逻辑层和渲染层还没有分开，只是在 Update 加入了帧判断机制用于追帧。后续加入网络或功能复杂起来，分离逻辑层和渲染层分开执行，这也是帧同步和一般 Update 之间的区别。

**评价：** ✅ 正确。比大多数面试者答得深。

**追问（服务器作用）：** 联网后服务器的具体作用是什么？只是转发吗？如果只是转发为什么不 P2P？

**帅老大回答：**
联网过后服务器主要作用就是发放消息，把消息发送到各个客户端，客户端再根据这个消息进行矫正。权威一点的服务器还需要对输入进行校验，主要是防止作弊。

**补充（架构导师）：** 还提到了"玩家挂机时服务器会做出相应措施"以及"P2P 帧同步是存在的，只不过现在最主要还是客户端和服务器模式"。

**评价：** ✅ 正确
