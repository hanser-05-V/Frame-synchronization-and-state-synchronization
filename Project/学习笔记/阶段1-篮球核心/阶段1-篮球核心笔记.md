## FixedMath — 定点数数学库

### 设计思路

帧同步要求确定性——任何平台上 Sqrt(4) 必须等于 2。Unity 的 `Mathf.Sqrt` 用 float，在不同 CPU/编译器下可能产生微小差异。所以自己实现定点数平方根。

### Sqrt 实现：Newton 法

```csharp
// FixedMath.cs
public static FixedInt Sqrt(FixedInt value)
{
    long n = (long)value._raw * FixedInt.SCALE;   // ×1000后开方
    long r = n;
    for (int i = 0; i < 20; i++)                  // Newton迭代
    {
        long next = (r + n / r) >> 1;
        if (next == r || next == r + 1 || next == r - 1)
            break;
        r = next;
    }
    return new FixedInt((int)r);                   // 结果含SCALE因子
}
```

**Newton法**（牛顿迭代法）求平方根：`r_{k+1} = (r_k + n/r_k) / 2`，迭代收敛到 `sqrt(n)`。
- 初始猜测 `r = n`（粗糙，但收敛快）
- 大约 5~8 次迭代后就稳定了，设 20 次上限兜底

### 为什么不用 Mathf.Sqrt？

| 方式 | 确定性 | 原因 |
|:----|:------:|:-----|
| `FixedMath.Sqrt(4)` | ✅ 永远=2000 (≈2.0) | 纯整数运算 |
| `Mathf.Sqrt(4f)` | ❌ 平台不同可能有0.000001差异 | float 精度不可控 |

## FixedVector3 — 定点数三维向量

### 设计思路

用 3 个 FixedInt 组合成向量。参考街篮2 FixedVector3，但 Demo 精简到核心方法。

### 关键方法

```csharp
public FixedInt magnitude => FixedMath.Sqrt(sqrMagnitude);   // 长度
public FixedVector3 normalized => this / magnitude;           // 归一化

public static FixedInt Dot(FixedVector3 a, FixedVector3 b)
    => a.x*b.x + a.y*b.y + a.z*b.z;                          // 点乘

public static FixedVector3 Cross(FixedVector3 a, FixedVector3 b)
{                                                              // 叉乘
    return new FixedVector3(
        a.y*b.z - a.z*b.y,
        a.z*b.x - a.x*b.z,
        a.x*b.y - a.y*b.x);
}

public static FixedInt Distance(FixedVector3 a, FixedVector3 b)
    => (a - b).magnitude;                                     // 距离
```

### ❌ 踩坑：normalized 每帧调用 Sqrt

```csharp
player.facing = new FixedVector3(mx, FixedInt.Zero, mz).normalized;
```

每次调用 `normalized` 都走了一次 `FixedMath.Sqrt`（20次Newton迭代）。
这是造成 `⚡追帧 1` 偶发的潜在原因。**优化方向**：只在方向改变时重算，不每帧算。

## BallPhysicsSystem — 球物理

### Euler 积分

```csharp
// 每帧：
velocity.y += Gravity * deltaTime;   // 重力加速
position   += velocity * deltaTime;  // 位移
```

参考街篮2 `BallPhysicalState.cs` 的 `Simulation` 方法。

### 篮筐碰撞检测

```csharp
// 判断条件：
// ① 球从篮筐上方经过 (上一帧y≥3.05 → 当前帧<3.05)
// ② 水平位置在篮筐半径±0.23m内
```

## PlayerStateMachine — 16态状态机

### 16 状态

```
Idle(待机) → Walk(走路) → Run(奔跑) → Dribble(运球) → Sprint(冲刺)
ShootReady(举球) → Shooting(投篮出手)
PassReady(传球准备) → Passing(传球中)
Steal(抢断) / Block(盖帽) / Jump(跳)
Rebound(抢篮板) / Stagger(硬直) / Fall(倒地) / GetUp(起身)
```

### 转换白名单设计

每对 `fromState → [allowedStates...]` 定义了合法转换：

```csharp
{ Idle, new[] { Walk, Run, Dribble, ShootReady, PassReady, Steal, Block, Jump, Stagger } }
{ Run,  new[] { Idle, Walk, Dribble, Sprint, ShootReady, Steal, Stagger } }
{ Shooting, new[] { Idle, Stagger } }
// ... 共16条
```

参考街篮2 `PlayerBaseState.CheckChangeList`。

### 与街篮2 的差异

| 维度 | 街篮2 | Demo |
|:----|:-----|:-----|
| 状态类 | 154 个类 + 反射 | **1个 switch + 白名单字典** |
| 转换机制 | 每个状态独立写 CheckChangeList | 统一白名单字典 |
| 状态数量 | 154 | 16 |

**Demo 选择 switch 而非 154 个类的原因**：154 个类的反射架构是可扩展工业设计，16 态 switch 足够 1v1 街篮 Demo，代码量少一个数量级。
