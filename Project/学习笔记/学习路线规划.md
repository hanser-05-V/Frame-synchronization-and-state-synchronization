## 🔴 阶段一：吃透单机代码（P0 — 最重要）

> 当前最紧急的问题：代码是 AI 生成的，你只理解原理但不熟悉具体实现。

| 优先级 | 任务 | 为什么 |
|:--:|------|------|
| ⭐⭐⭐ | **手写 FixedInt.cs** | 定点数是帧同步的基石。你会用但如果被问"乘法怎么实现"、"为什么是 1000 倍率"——能讲清楚吗？ |
| ⭐⭐⭐ | **手写 FrameInput.cs** | 4 字节位域压缩。试一试自己写：给定 uint _raw，手写 pos/yaw/btn 的 get/set 位运算 |
| ⭐⭐⭐ | **手写 FrameBuffer.cs** | 环形缓冲。面试官问"环形缓冲满了一直覆盖前面的数据，会不会丢失关键信息"——怎么答？ |
| ⭐⭐ | **读懂 FrameEngine.Update()** | while 追帧机制、OnRequestInput 回调拉取、MarkRead 延迟消费——这些细节全部读懂 |
| ⭐⭐ | **读懂 GameController** | Input 收集 → OnFrameUpdate → HandlePlayback 的完整链路，自己画一遍流程图 |
| ⭐⭐ | **读懂录制回放链路** | StartRecording(重置帧号) → UpdateFrame(recordedFrameCount++) → StartPlayback → ReadInputs(读recordedInputs) → 轨迹复现 |
| ⭐ | FrameDebugger.cs | 数据单例，理解"统一数据源→双视图"的架构 |
| ⭐ | FrameSyncWindow.cs | EditorWindow——如果你以后做 Unity 开发，Editor 扩展是常用技能 |

## 🟢 阶段三：网络帧同步（P2）

**需要的技能清单：**

| 技能 | 难度 | 说明 |
|------|:--:|------|
| C# Socket / UDP 基础 | 🟡 | 需要理解 TCP/UDP 的区别、端口、bind/connect/send/recv |
| 序列化 | 🟢 | 你的 Input 本身就是 uint，不需要定协议；但要理解"协议=通信格式" |
| 预测回滚理论 | 🟡 | 你已经理解了大半——联网后每个客户端本地预测，服务器回包校验不一致就回滚 |
| KCP / WebSocket | 🔴 | 按需选用。单机→联网最常见的方案是 WebSocket（简单）或 KCP（更难但更快） |
| 多线程 | 🔴 | 街篮2 用独立线程跑逻辑和网络——你现在是单线程 Demo |

### 网络阶段最小化 Demo 建议

```
单机 Demo 的基础上加：
  ① 一个 C# Console 程序作为"服务器"（只转发，不校验）
  ② 一个 Unity Editor 作为"客户端1" → 连服务器
  ③ 一个 Build 出来的 exe 作为"客户端2" → 连服务器
  ④ 两个窗口分别操控方块 → 互相看到对方的移动
```

**不要一上来就做预测回滚！** 先做最基础的"服务器转发 Input → 客户端消费"，把联机跑通再说。
